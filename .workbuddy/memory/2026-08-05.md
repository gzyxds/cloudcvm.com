# 2026-08-05

## cloudcvm.com 项目分析报告（核实版）

对当前工作区 cloudcvm.com 做了"先验证、再下结论"的仔细分析，覆盖文档与真实代码的比对。

### 已核实的技术栈
- Next.js 15.4.8 (App Router, `output: 'export'` 静态导出), React 19, TS 5.8, Tailwind CSS 4.1.11（v4 `@theme` 写法，**无 tailwind.config.js**）
- 动画：framer-motion（37 文件）、Three.js + postprocessing（仅 PixelBlast.tsx 单点使用）
- 47 个路由目录；首页用 11 个 `dynamic()` + 骨架屏占位（防 CLS），性能实践优于文档描述
- 集中式导航数据：`src/data/navigation.ts`（文档未提及）

### 文档与现实的偏差（重点）
1. README/Project.md 声称有 `/login` `/register` 认证系统 → **实际无 `(auth)` 路由组**，登录走外部 console.cloudcvm.com
2. CODE_WIKI 声称依赖 gsap@3.14.2 → **package.json 无 gsap，代码也未 import**（虚假声明）
3. CODE_WIKI 称 sitemap 33 页 → 实际 seo.config.ts 列出 **40** 条
4. README/CODE_WIKI 描述的目录结构（[product] 路由、(auth) 组）与真实不符

### SEO / 路由一致性问题
- sitemap 仅 40 条，实际 47 路由目录，**缺失 blog / cbm / gpu / lighthouse / token**
- `blog/` 是动态路由（`blog/[slug]`、`blog/search`、`blog/rss.xml`），**无索引页且未进 sitemap** → 博客内容不被收录

### 代码健康 / 异味
- 死文件：`src/components/MegaMenu copy.tsx`（未引用）、`public/images/logos/logo copy.svg`（未引用）、`参考设计/html copy.html`
- 品牌色分裂：设计系统用 `#3860F4`（brand-500 + theme-color），但 AI 组件（如 BananaProductPage）硬编码 `#0055ff` 旧蓝
- 无 `error.tsx` 全局错误边界（project_rules 已列为最佳实践但未落地）
- `out/` 构建产物中含 `logo copy.svg` 等残留

### 结论
项目骨架扎实、首页性能优化到位；主要风险在**文档失准、SEO sitemap 滞后、品牌色/死文件未清理、Three.js 单点重依赖**。建议按 P0(补 sitemap/统一品牌色) → P1(删死文件/加 error.tsx) → P2(评估 three.js 去留) 推进。
