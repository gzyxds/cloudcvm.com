- 首页 = Header + VideoCarousel + 18 楼层 + Footer；楼层分布在 `sections/home`(10) 与 `sections/shared`(8)

- 18 楼层仅 2 个是服务端组件（LogoClouds、Testimonials），其余带 `'use client'`

## 修复移动端进入页面被拉到「产品优势」区块

**现象**：移动端从菜单点「云服务器ECS」进 `/ecs`，页面不停在头部，而是直接滚到 `Superiority.tsx`（产品优势）区块。

**根因**：`src/components/sections/shared/Superiority.tsx` 的标签栏定位 effect 依赖 `[activeTabId]`，**首次挂载也会执行**；内部用 `activeEl.scrollIntoView({ inline:'center', block:'nearest' })`。`scrollIntoView` 会滚动**所有可滚动祖先（含页面本身）**，而进入页面时标签栏在视口下方 → 页面被向下滚动把它带进视野。桌面端因 `matchMedia('(max-width:768px)')` 守卫而不触发，故只在移动端复现。

**修复**（`Superiority.tsx`，未改 CSS、未改视觉）：

1. 新增 `tabBarRef` 指向 `role="tablist"` 的 `.tabBar`（移动端 CSS 里它是 `overflow-x:auto` 的横向滚动容器）；
2. 新增 `prevTabIdRef` **跳过首次挂载**，只在用户真正切换标签时滚动；
3. 用 `container.scrollTo({ left })` + `getBoundingClientRect` 计算居中位移，**只滚动标签栏自身**，彻底移除 `scrollIntoView`，页面纵向滚动不再可能被本组件触发；
4. 删掉 `matchMedia('(max-width:768px)')` 守卫——它是在和 CSS 断点重复维护，且现在已无必要（桌面端 `.tabBar` 非滚动容器，`scrollTo` 为 no-op）。

验证：`tsc --noEmit` exit 0；`eslint` 该文件 0 error（仅既有 max-lines 告警）；`prettier --check` 通过。**未做真机/浏览器验证**。

**同类排查结论**（全库 grep `scrollIntoView|scrollTo`）：`Advantage.tsx:358`、`BananaProductPage.tsx:244`、`Scenario.tsx`、`HotProducts.tsx`、`PriceCard.tsx`、`FloatingToolbar.tsx` 的滚动调用**均在点击/事件回调内**，不是挂载即执行，无同类隐患。
