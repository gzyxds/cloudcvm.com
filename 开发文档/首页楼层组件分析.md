# 首页楼层组件分析

> 分析对象：`src/app/page.tsx` 及其引用的全部「楼层」区块组件  
> 分析时间：2026-10-05；以当日工作区源码（含尚未提交的修改）为准  
> 代码基线：Next.js 16.3.5（`output: 'export'` 静态导出）+ React 19 + Tailwind v4 + framer-motion  
> 官方规范与跨文档问题清单见 [Next.js 官方规范审查与文档校对](./Next.js官方规范审查与文档校对.md)。
>
> **特别说明**：`dynamic()` 是代码拆包/加载边界，不等于“用户滚动到才加载”；是否按视口推迟下载需通过浏览器网络面板实际测量。

---

## 一、总体结构

首页由 **1 个视频轮播 + 18 个楼层区块 + Header/Footer** 堆叠而成，页面结构按「视觉冲击 → 功能展示 → 解决方案 → 商业转化 → 社会证明 → 行动引导」的转化漏斗排布。

楼层组件分布在三个目录：

| 目录 | 定位 | 首页引用数 |
| --- | --- | --- |
| `components/sections/home` | 首页专用楼层 | 9 |
| `components/sections/shared` | 跨页复用楼层 | 9 |
| `components/sections/ai` | AI 相关页专用（首页未引用） | 0 |

`page.tsx` 中 18 个楼层按**加载策略**分成两批，这是本模块最重要的架构决策：

### 静态导入（8 个楼层）

`Hero` · `ServiceTabs` · `PrimaryFeatures` · `Leftright` · `Rightleft` · `Solution` · `TwoColumnShowcase` · `Scenario`；此外 `Header`、`Footer`、`VideoCarousel` 也为静态导入。

### `dynamic()` 导入（10 个楼层）

`Price` · `CapabilityGrid` · `BentoGrids`（别名 `CallToAction`）· `Advantage` · `Testimonials` · `Customer` · `Zone` · `Faqs` · `LogoClouds` · `CatSections`。

**注意**：实际顺序中 `Price` 是第 3 个楼层（`page.tsx:120`），并非“首屏以下”；`VideoCarousel` 才是首页最顶部的轮播。不能以“首屏以上全静态导入、首屏以下才动态”概括当前实现。既有构建记录发现特定骨架在首屏造成闪烁，但这属于**当前产品体验约束**，不是 Next.js 官方禁止 `loading.tsx` 或 `dynamic()` 的规则；应以实际构建产物和 CLS/LCP 测试决定取舍。

## 二、楼层组件的统一骨架

18 个楼层在结构上高度一致，可归纳为同一套模板：

```
<section>                      ← 顶层语义容器，承担背景 / 内边距
  <Container>                  ← max-w-[1800px] mx-auto px-4 sm:px-6 lg:px-8
    标题区 (h2 + p)            ← 有的用 <SectionHeader>，多数手写
    主体区 (卡片 / Tab / 轮播)
    底部 CTA 链接（可选）
  </Container>
</section>
```

- **容器统一**：`components/ui/Container.tsx` 是所有楼层的公共外层，宽度锁定 `1800px`（适配超宽屏）。
- **标题区不统一**：只有 `ui/SectionHeader.tsx` 一个公共组件，且仅被 AI 相关页使用；首页楼层几乎全部**手写** h2+p，字号/间距/对齐方式各不相同（详见第五节）。
- **背景策略**：多数楼层用 `inline style` 挂 `background-image: url(/images/background/background-N.webp)`，背景图与组件强耦合在 JSX 里。

## 三、交互模式（存在明显重复）

首页楼层的交互收敛为 4 类模式，但每类都有 2–4 个独立实现：

### 1. Tab 切换 + 悬停防抖
`ServiceTabs` / `Leftright` / `TwoColumnShowcase` / `PrimaryFeatures` 共用 `hooks/useDebouncedHover.ts`（100ms 防抖，统一负责卸载清理）。
✅ 已收敛为公共 Hook，注释里明确记录了「此前四处重复实现、三处遗漏卸载清理」的收敛过程，是很好的实践。

### 2. 横向手风琴（PC 展开 / 移动堆叠）
`Solution` / `PrimaryFeatures` / `BentoGrids` 三个楼层结构几乎同构：
- 状态：`expandedIndex` + `setExpandedIndex`
- PC：`flex` 容器 + 卡片 `flex-[2.5]` / `flex-[0.8]` 宽度过渡，`hidden lg:flex`
- 移动：`lg:hidden` 竖向堆叠
- 切换：`onMouseEnter`

三者**未抽公共组件**，卡片宽度比例、圆角、过渡时长各自硬编码，是首页最集中的重复代码。

### 3. 原生 scroll-snap 轮播
`Scenario` 用原生 CSS scroll-snap + `requestAnimationFrame` 节流计算分页，未引入第三方轮播库，且是**唯一**做了 `useReducedMotion()` 无障碍降级（降低动效）的楼层。

### 4. 左列表 / 右预览联动
`Customer`（左客户列表 + 右图片）、`TwoColumnShowcase`（左手风琴 + 右图预览）、`Rightleft`（左文 + 右图）共享同一视觉范式。

## 四、动效与样式体系

- **入场动画**：统一用 framer-motion `whileInView` + `viewport={{ once: true }}`；`Hero` 定义了 `EASE_OUT_EXPO = [0.16, 1, 0.3, 1]` 缓动常量并复用。
- **无障碍降级缺失**：18 个楼层中**仅 `Scenario`** 使用了 `useReducedMotion()`，其余楼层的 `whileInView` 动画在「减少动效」偏好下仍会播放。
- **品牌色令牌**：`styles/tailwind.css` 用 Tailwind v4 `@theme` 定义 `--color-brand-*`（主色 `#3860f4`），并别名到 `primary-*` / `indigo-*` / `accent-*` 三套命名。
- **CSS Module 兜底**：`Advantage` / `LogoClouds` / `ProductTraits` / `Superiority` 因动画复杂，使用 `components/css/*.module.css`。

## 五、发现的问题（按优先级）

### 🔴 P1 — 色值双轨，未收敛到品牌令牌
品牌主色令牌是 `#3860f4`（`brand-500`），但多个楼层**硬编码**了另一套蓝色：

| 文件 | 硬编码色值 | 说明 |
| --- | --- | --- |
| `CapabilityGrid.tsx` | `#0055ff` `#eff6ff` `#0F172A` `#64748B` | 全文件硬编码 |
| `Scenario.tsx` | `#1664ff` `#1d2129` `#4e5969` `#F7F8FA` | 全文件硬编码 |
| `Customer.tsx` | `#0055ff` | 激活态 / 图标 |
| `Rightleft.tsx` | `#0052d9` `#091221` `#4b5b76` | 全文件硬编码 |
| `CatSections.tsx` | `#0055ff` | hover 边框 |

同一页面出现 `#3860f4` / `#0055ff` / `#1664ff` / `#0052d9` 四种品牌蓝，换主题或统一品牌色时需全局搜索替换，是首页最大的技术债。

### 🟠 P2 — 骨架屏高度写死，仍有 CLS 风险
10 个动态导入楼层多数使用 `<SectionSkeleton />`，占位高度**固定 400px**（`LogoClouds` 为 200px），`Price` 也在其中且位置靠前。真实楼层高度不一致，骨架→内容切换可能造成 CLS；不能假定它们只在滚动进入视口时才切换。建议先检查导出 HTML、网络瀑布与 Performance 面板，再决定对靠前楼层取消动态导入，或给其余楼层设置接近真实布局的稳定占位。

### 🟠 P2 — 横向手风琴三处重复
`Solution` / `PrimaryFeatures` / `BentoGrids` 的手风琴逻辑未抽象，属于典型的「复制粘贴三份」。可抽 `useAccordion` + `<AccordionCard>`，把宽度比例、圆角、过渡做成参数。

### 🟡 P3 — 区块锚点 `id` 不统一
只有部分楼层带 `id`：`Solution`(#solutions)、`BentoGrids`(#features)、`CapabilityGrid`(#cloud-features)、`FAQSection`(#faq)。其余楼层无 id。这会影响页内锚点跳转与 `hooks/useActiveSection.ts`（导航高亮）的可靠性，且命名风格不一致（`solutions` vs `cloud-features`）。

### 🟡 P3 — 图标库双轨
`@heroicons/react`（约 50 文件）与 `lucide-react`（约 14 文件）并存，**同一首页内混用**：`Hero`/`Leftright` 用 lucide，`PrimaryFeatures`/`Solution`/`Zone` 用 heroicons。增加产物体积与风格不一致风险。

### 🟡 P3 — 数据内联，文件偏大
绝大多数楼层把数据常量（`TAB_CATEGORIES` / `solutionsData` / `capabilities` / `serviceTabs`…）直接写在组件文件顶部，仅 `sections/ai/data/products.ts` 做了抽离。叠加「首页 + 楼层」双职责后，部分文件偏大（`ServiceTabs` 42KB、`Faqs` 29KB、`PrimaryFeatures` 26KB）。

### 🟡 P3 — 服务端/客户端边界
`LogoClouds` 与 `Testimonials` 是纯渲染的 Server Components，首页多数楼层因交互为 Client Components。**静态导出不会取消 Server Components 的价值**：它们在构建时产出 HTML/RSC 数据、不会为组件本身引入客户端 JS。建议逐个核查无需交互的模块并缩小客户端边界；但 Server Component 被 `dynamic()` 导入不等于该组件会在滚动时才下载。

## 六、结论

首页楼层模块已有公共 Hook 与容器等复用实践，但“首屏静态 / 首屏以下 dynamic”的旧结论与 `page.tsx` 不符：`Price` 位于第三层却使用动态导入；`dynamic()` 也不代表按视口加载。优化决策应以静态导出 HTML、网络瀑布、Core Web Vitals 与视觉回归为依据。

主要技术债集中在三点，按性价比排序：

1. **色值收敛**（P1）：把 `#0055ff` / `#1664ff` / `#0052d9` 等硬编码统一到 `brand-*` 令牌，收益最大。
2. **骨架高度贴近真实楼层**（P2）：消除懒加载楼层的 CLS。
3. **横向手风琴抽象**（P2）：消除三处重复实现。

后续可渐进推进：锚点 id 规范化 → 图标库收敛 → 数据抽离 → 动效 `useReducedMotion` 补全。
