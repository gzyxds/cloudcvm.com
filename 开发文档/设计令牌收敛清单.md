# 设计令牌收敛清单（硬编码 / 原始色板 → 令牌）

> **用途**：作为「全站统一设计风格」的后续逐步收敛待办。目标是把散落在业务组件里的**硬编码色值**与 **Tailwind 原始色板（slate / gray / blue / indigo）**统一替换为 `src/styles/tailwind.css` 中定义的 **brand / neutral 令牌**。
>
> **生成时间**：2026-10-05（2026-10-05 修订：修正统计口径、新增 `blue/indigo` 映射、标注首批完成项）
> **统计口径**：`src/**/*.{tsx,ts,css}`，hex 用 `#[0-9a-fA-F]{6}` / `#[0-9a-fA-F]{8}`；色板类用 `\b[a-z-]*(slate|gray|blue|indigo)-[0-9]{2,3}\b`
> **设计源头**：[`src/styles/tailwind.css`](../src/styles/tailwind.css)（令牌 + 档位类，改一处全站生效）
> **相关文档**：[技术文档](./技术文档.md) · [首页楼层组件分析](./首页楼层组件分析.md) · [代码规范与优化](./代码规范与优化.md)

## 一、目标与原则

1. **单一事实来源**：颜色 / 圆角 / 阴影 / 字号一律走 `tailwind.css` 的令牌或档位类，业务组件内不写十六进制。
2. **一次一文件、改完即验**：不做全仓大爆炸式替换，按下面的批次逐个文件收敛，每个文件改完跑 `tsc --noEmit` + `eslint` + `prettier --check` + 肉眼比对。
3. **例外允许保留**：语义状态色、图片上的白色文字遮罩、SVG 素材、WebGL/Canvas 参数、动态数据值（详见第四节）。
4. **提醒**：统一档位 ≠ 全站同一个尺寸。标题按 `section-title-xl / lg / 标准` 分档，间距按 `section-y / section-y-sm` 分档，不要都套成一档。

> **为什么只有 `gray-900 → neutral-950` 不是数字平移**：令牌里 `neutral-800` 与 `neutral-900` 取值相同（都是 `#1d273f`）。若 `gray-900` 也平移到 `neutral-900`，暗色模式的「页面底」会和「卡片底」撞成同色。因此把最深一档让给 `neutral-950`（`#0f172a`），保持「页面底 < 卡片底 < 嵌套底」的层次。

### E. 品牌蓝统一：`blue-*` / `indigo-*` → `brand-*`

> 这两族是「品牌蓝的原始色板替身」，体量比灰阶还大（全站 `blue-*` 647 处、`indigo-*` 35 处）。`blue-600` 是页面里最常见的**主按钮底色**、`blue-700` 是它的 hover，因此按设计指南落到 `brand-500` / `brand-600`。

| 现用类                            | 目标                               | 备注                  |
| --------------------------------- | ---------------------------------- | --------------------- |
| `blue-50 / 100 / 200 / 300 / 400` | `brand-50 / 100 / 200 / 300 / 400` | 浅色档数字位平移      |
| `blue-500`                        | `brand-500`                        |                       |
| `blue-600`                        | `brand-500`                        | **主按钮底色 → 主色** |
| `blue-700`                        | `brand-600`                        | **主按钮 hover**      |
| `blue-800`                        | `brand-700`                        |                       |
| `blue-900`                        | `brand-800`                        |                       |
| `blue-950`                        | `brand-900`                        |                       |
| `indigo-50 … indigo-900`          | `brand-50 … brand-900`             | 旧别名，数字位平移    |

> **保留不动**：语义 / 状态 / 装饰色板 —— `green / emerald`（成功、在线）、`red / rose`（错误、警示）、`amber / yellow / orange`（强调、折扣）、`sky / cyan`（科技青）、`purple / violet / pink`（AI 强调与多色渐变）。这些属于设计指南允许的「业务强调色」例外；若要收敛，需先在 `tailwind.css` 定义 `--color-success / warning / danger / info` 等语义令牌。

## 六、执行建议

**可机械替换（脚本 / 批量查找替换，风险低）**

> 已把映射固化成脚本 `scripts/token-migrate.mjs`（支持 `--dry` 预演），下面的 1–3 条它都能处理：
>
> ```bash
> node scripts/token-migrate.mjs --dry src/app/ssl/page.tsx   # 先看命中
> node scripts/token-migrate.mjs src/app/ssl/page.tsx         # 落地
> npx prettier --write src/app/ssl/page.tsx                   # 必须：重排类名
> ```

1. 任意值类里的 hex：`text-[#0055ff]` → `text-brand-500`、`bg-[#0055ff]/8` → `bg-brand-500/8`、`border-[#E2E8F0]` → `border-neutral-200`。约占 90%。
2. `slate-* / gray-*` 按第三节 D 平移；`blue-* / indigo-*` 按第三节 E 映射到 `brand-*`。
3. 同一文件里重复出现的近白淡蓝（`#eff6ff` 等）先统一成 `brand-50` 再提交。

**需人工判断（不要盲跑脚本）**

- `linear-gradient(...)` / `box-shadow` / `rgba(...)` 里的色值：换成 `var(--color-brand-500)` 或 `color-mix(in srgb, var(--color-brand-500) X%, transparent)`（注意 Tailwind 任意值内空格要写成 `_`），不能直接套类。
- 深色面（`bg-gray-700/800/900`）的语义归位（见第三节 D 的说明）。
- CSS Modules（`*.module.css`）内：用 `var(--color-*)` / `var(--radius-*)`，不要另起硬编码。
- 促销 / 状态 / 分类色：先决定是否新增语义令牌，再统一。

**每个文件改完即跑**

```bash
npx tsc --noEmit
npx eslint <改动文件> --quiet
npx prettier --write <改动文件>   # 令牌改名会触发 Tailwind 类名重排，必须再格式化
git diff --check
```

> 经验：`prettier-plugin-tailwindcss` 会按类名重新排序，所以替换后**必须**跑一次 `prettier --write`，否则 `prettier --check` 会失败（且 pre-commit 钩子会自动改）。

**回归**：改动集中的页面（如 `/ssl`、`/ecs`、`/windows`）改完后本地 `npm run dev` 肉眼比对关键区块，确认无暗色模式失效。

grep -rhoE '#[0-9a-fA-F]{6}|#[0-9a-fA-F]{8}' src --include='*.tsx' --include='*.ts' --include='*.css' | tr 'A-F' 'a-f' | sort | uniq -c | sort -rn | head -30
