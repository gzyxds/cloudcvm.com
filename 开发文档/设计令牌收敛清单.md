# 设计令牌收敛清单（硬编码 / gray-\* → 令牌）

> **用途**：作为「全站统一设计风格」的后续逐步收敛待办。目标是把散落在业务组件里的**硬编码色值**与 **Tailwind 原始灰阶（slate / gray）**统一替换为 `src/styles/tailwind.css` 中定义的 **brand / neutral 令牌**。
>
> **生成时间**：2026-10-05
> **统计口径**：`src/**/*.{tsx,ts,css}`，正则 `#[0-9a-fA-F]{3,8}` 与 `[a-z-]*-(slate|gray)-[0-9]{2,3}`
> **设计源头**：[`src/styles/tailwind.css`](../src/styles/tailwind.css)（令牌 + 档位类，改一处全站生效）
> **相关文档**：[技术文档](./技术文档.md) · [首页楼层组件分析](./首页楼层组件分析.md) · [代码规范与优化](./代码规范与优化.md)

---

## 一、目标与原则

1. **单一事实来源**：颜色 / 圆角 / 阴影 / 字号一律走 `tailwind.css` 的令牌或档位类，业务组件内不写十六进制。
2. **一次一文件、改完即验**：不做全仓大爆炸式替换，按下面的批次逐个文件收敛，每个文件改完跑 `tsc --noEmit` + `eslint` + 肉眼比对。
3. **例外允许保留**：语义状态色、图片上的白色文字遮罩、SVG 素材、WebGL/Canvas 参数、动态数据值（详见第四节）。
4. **提醒**：统一档位 ≠ 全站同一个尺寸。标题按 `section-title-xl / lg / 标准` 分档，间距按 `section-y / section-y-sm` 分档，不要都套成一档。

## 六、执行建议

**可机械替换（脚本/批量查找替换，风险低）**

1. 任意值类里的 hex：`text-[#0055ff]` → `text-brand-500`、`bg-[#0055ff]/8` → `bg-brand-500/8`、`border-[#E2E8F0]` → `border-neutral-200`。约占 86%。
2. `slate-* / gray-*` 数字位平移 → `neutral-*`（深色面按第三节 D 的提示处理）。
3. 同一文件里重复出现的 `#eff6ff` → `bg-brand-50` 之类，先统一再提交。

**需人工判断（不要盲跑脚本）**

- `linear-gradient(...)` / `box-shadow` / `rgba(...)` 里的色值：需换成 `var(--color-brand-500)` 或 `color-mix(in srgb, var(--color-brand-500) X%, transparent)`，不能直接套类。
- 深色面（`bg-gray-800/900`）的语义归位。
- CSS Modules（`*.module.css`）内：用 `var(--color-*)` / `var(--radius-*)`，不要另起硬编码。
- 促销 / 状态 / 分类色：先决定是否新增语义令牌，再统一。

**验证（每个文件改完即跑）**

```bash
npx tsc --noEmit
npx eslint <改动文件> --quiet
npx prettier --check <改动文件>
git diff --check
```

**回归**：改动集中的页面（如 `/price`、`/ecs`、`/ssl`）改完后本地 `npm run dev` 肉眼比对关键区块，避免出现色差或暗色模式失效。
