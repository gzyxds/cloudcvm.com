# CloudCVM.com 项目长期记忆

## 项目概况

- Next.js 16.3.5 App Router + React 19.3 + TypeScript 5.8 + Tailwind CSS 4.1（2026-09-22 自 15.4.8 升级）
- **静态导出**：`next.config.js` → `output: 'export'`、`images.unoptimized: true`、`trailingSlash: true`
- 静态导出约束：不能引入任何需要 Node 运行时的能力（如 next/image 默认 loader、SSR-only 库）
- 无后端 API；48 个路由页、21 个 layout
- 文档（均在 `开发文档/`）：
  - `代码规范与优化方案.md` — 规范主文档（§13/§14 执行记录）
  - `代码规范与优化.md` — 分步执行记录（S1~S10、P1~P3 会话日志）
  - `技术文档.md` — 项目 Wiki（架构/目录/组件/依赖）
  - `项目长期记忆.md` — 本文件（架构事实、踩坑、待办）

## 重要架构事实

- `src/styles/tailwind.css` 是全站 Design Token 源（brand 色阶、radius、shadow、keyframes）
  - **Tailwind v4 默认扫描根目录所有文件含 .md**，已在文件顶部用
    `@source not "../../**/*.md"` 排除文档，避免文档示例代码生成垃圾 CSS
  - 主色是 **`brand-500 = #3860f4`**；`indigo-*` / `primary-*` 都是它的迁移期别名
- 21 个 layout.tsx：**14 个**用 `src/components/layout/SiteShell.tsx`（retail 通过
  `className="bg-white"` 覆盖背景）；**6 个**（agent/contact/demo/ecommerce/human/support）
  是纯 metadata layout（`return <>{children}</>`，页面自行渲染 Header/Footer）。
  **SEO metadata 分散在各 layout，改动时不能丢**
- `three` + `postprocessing` 仅被 `src/components/effects/PixelBlast.tsx`(730 行) 使用，
  只服务 `/human` 一个路由，已改 `dynamic({ssr:false})`
- 图片流水线三个脚本（**均已修复，均可加 `--dry-run`**，按序执行）：
  1. `scripts/optimize-images.js` — PNG/JPG → WebP
  2. `scripts/update-image-refs.js` — 改写代码引用（**必须扫 `.css`**）
  3. `scripts/cleanup-originals.js` — 删原图（**先反查引用再删**）
  - **决定不挂 `prebuild`**：转 WebP 是一次性资源迁移，结果应提交进仓库，
    挂构建期会导致构建变慢 + 产物不确定
  - `scripts/` 目录**被 ESLint 忽略**，脚本里 `console.log` 不产生 warning
  - 三个脚本的目录清单互相耦合（`targetDirs`），改一个必须同步另两个

## 踩过的坑（务必记住）

- **「PNG 转 WebP 一定更小」是错的**。实测 11 个候选里 **6 个转完更大或收益为负**：
  扁平/图形类 PNG（截图、纯色块、UI 稿）用 PNG 调色板无损压缩本就很紧，
  转有损 WebP 反而膨胀（`solutions/finance.png` 129.8→189.7 KB，+46%）。
  → 转换脚本必须有「变大就丢弃」+「收益 < 15% 就丢弃」两道闸门
- **本仓反复出现「删图不删引用」**：commit `167f381` 以「移除未使用的图片资源」为名
  删了 `Carousel5.png`/`contacts.png`，引用没跟着改 → ecommerce 页面留 4 处 404。
  任何删资源操作都必须先反查引用
- **超大 `.svg` 未必是矢量**：`public` 下曾有 20 个 svg 共 7.06 MB，其中 4 个是
  「内嵌 base64 位图的假 SVG」（`<image>`+base64）共 5.5 MB——S10 已全部转 WebP
  （saas 3.49MB→63KB 等），现 svg 仅剩 16 个真矢量。
  → **判断图片问题要看文件里装的是什么，不能只看扩展名**
- **`loading.tsx` 在静态导出下会变成"首屏闪现"**：S2 新增的 `src/app/loading.tsx`
  被 Next 烘焙进导出的 HTML 作为**首屏可见内容**（真实内容藏在 `<div hidden id="S:0">`，
  hydration 后才替换）→ 每次硬刷新先闪现骨架屏。**2026-09-21 已删除该文件**。
  **2026-09-22 同类问题在 `dynamic(..., { loading })` 上再现**：视频轮播的 `h-[500px]` 骨架
  在 flex 布局中塌缩为 0 高 → hydration 后真实轮播（400/500/600px）插入，**首屏内容整体下跳**。
  已修复：首屏以上区块改**静态导入** + 视频去掉 `autoPlay` 属性、`preload` 固定 `metadata`
  （视频字节仍在挂载后由 `play()` 才下载）。**规则：静态站首屏以上不放任何 Suspense 加载态**
- **dev 与 build 的并发关系（Next 16 起已变）**：dev 产物改写入 `.next/dev`，二者**可并行**（2026-09-22 实测通过）。
  但**同一项目同时跑两个 `next dev` 实例会互相冲突**，并让并行的 build 报 `Cannot find module for page: /xxx`
  （同日实测：两个 dev 实例 + build 复现）。遇到该报错先查 dev 实例数量；仍可用 `rm -rf .next` 兜底重建
- **Next 16 静态导出 RSC 预取路径错位**（上游 vercel/next.js#85374，16.x 未修）：**仅 Windows 本地构建**会写出
  `out/<route>/__next.<seg>/__PAGE__.txt`，客户端却请求 `<route>/__next.<seg>.__PAGE__.txt` → 404。
  **Linux（CI / Cloudflare）构建实测没有该嵌套目录**（postbuild 自动跳过），生产不受影响；**导航也不受影响**
  （点击时回退 `<route>/index.txt`），只是 Windows 本地预览时预取失效 + 控制台 404 噪音。
  已加 `scripts/fix-rsc-prefetch.js`（`postbuild` 自动执行）复制一份正确命名的负载，让本地产物与生产一致
- **Windows 本地通过 ≠ Linux（CI）通过**：2026-09-22 CI 首次真实运行，一次暴露两个只在
  Linux 干净检出下才会出现的问题——
  1. **`next-env.d.ts` 曾被 .gitignore 忽略**：它承载 `next/image` 的类型声明
     （`*.png` 等模块导入），不提交则全新 clone 上 `npm run typecheck` 直接挂（TS2307）。
     **已从 .gitignore 移除并入库**；
  2. **「仅改大小写」的文件重命名 git 感知不到**：`components/css/LogoClouds.module.css`
     磁盘上已改名，索引里仍是 `Logoclouds.module.css` → Windows 大小写不敏感照常构建，
     Linux 报 `Can't resolve`。**改大小写要用 `git mv -f` 或 `git rm --cached` + `git add`**。
     → 结论：**代码改动最终以 CI（Linux）为准**；本地 Windows 构建通过只是必要条件
- **写「资源引用校验」不要只扫自己关心的扩展名**：一次只匹配 `png|jpe?g|webp|svg`
  的校验，完全漏掉了 `/videos/*.mp4`
- **「有同名 WebP」≠「已切换到 WebP」**：删原图前必须确认代码里已无该原格式引用

## 会话决策记录（2026-09-21）

### P2b：Advantage SVG 上 SVGO — 跳过

- 5 个 SVG 共 1.7 MB，含 `<animateMotion>` 管道流动动画（`dcim-pipe-flow-system` 类）+ CSS clip-path
- SVGO 可能破坏动画时序或 clip-path 几何
- 已有 `prefers-reduced-motion: reduce` 降级（CSS 隐藏 `.dcim-pipe-flow-system`），但正常用户仍会看到动画
- 需视觉回归验证，风险 > 收益
- `Zone.tsx` 第 32 行注释自曝是「品牌示意值」——业务合规风险，优先级高于技术优化
