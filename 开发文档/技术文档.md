## 1. 项目整体架构

### 1.1 架构概览

本项目是一个 **100% 纯前端、静态导出的 Next.js 16 企业官网**，无后端服务、无 API 路由、无数据库。所有页面在构建时预渲染为静态 HTML/CSS/JS，部署到任意静态文件服务器（如 Nginx、CDN）。

```
┌─────────────────────────────────────────────────────────────┐
│                     浏览器 (Client)                          │
├─────────────────────────────────────────────────────────────┤
│  React 19 Components  │  Framer Motion  │  Three.js（PixelBlast）│
├─────────────────────────────────────────────────────────────┤
│                   Next.js 16 App Router                      │
│  ┌─────────┐ ┌──────────┐ ┌──────────┐ ┌───────────────┐  │
│  │  首页   │ │ 云产品页 │ │  AI页面  │ │  解决方案页   │  │
│  │  (/)    │ │ (/ecs等) │ │ (/ai等)  │ │ (/ecommerce等)│  │
│  └─────────┘ └──────────┘ └──────────┘ └───────────────┘  │
├─────────────────────────────────────────────────────────────┤
│              静态构建输出 (next build → out/)                 │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 页面转化漏斗设计

首页遵循"视觉冲击 → 功能展示 → 解决方案 → 商业转化 → 社会证明 → 行动引导"的用户浏览路径:

```
Header → VideoCarousel → Hero → ServiceTabs → Price → PrimaryFeatures
→ Leftright → Rightleft → Solution → TwoColumnShowcase → Scenario
→ CapabilityGrid → CallToAction(BentoGrids) → Advantage
→ Testimonials → Customer → Zone → Faqs → LogoClouds → CatSections → Footer
```

### 1.3 三大业务线

| 业务线         | 路由前缀                                                  | 说明                                     |
| -------------- | --------------------------------------------------------- | ---------------------------------------- |
| 云计算基础设施 | `/ecs`, `/host`, `/server`, `/windows`, `/cdn`, `/ssl`    | 云服务器、虚拟主机、独立服务器、CDN、SSL |
| 人工智能产品   | `/ai`, `/chat`, `/work`, `/paper`, `/human`, `/video`     | 艺创AI、数字分身、知识库、论文创作       |
| AI 解决方案    | `/banana`, `/jimeng`, `/jmdraw`, `/sora`, `/ppt` 等 12 个 | 面向特定场景的 AI 工具页面               |
| 行业解决方案   | `/ecommerce`, `/retail`, `/mobile`, `/game`, `/gov` 等    | 电商、金融、游戏、政府等行业云方案       |

## 4. 模块职责说明

### 4.1 页面路由模块 (`src/app/`)

使用 Next.js 16 **App Router** 的文件系统路由。每个路由目录对应一个 URL 路径。

#### 4.1.1 系统级文件

| 文件                    | 职责                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `src/app/layout.tsx`    | **根布局组件** - 全局 HTML 结构、SEO 元数据、结构化数据(JSON-LD)、搜索引擎验证标签、Analytics、FloatingToolbar。所有子页面自动继承。 |
| `src/app/page.tsx`      | **首页组件** - 按转化漏斗编排区块；首屏以下区块用 `dynamic()` 延迟加载。                                                             |
| `src/app/error.tsx`     | **全局错误边界** - 自带 Header/Footer（错误时路由布局不渲染）。                                                                      |
| `src/app/not-found.tsx` | **404 页面** - 自定义未找到页面。                                                                                                    |
| `src/app/robots.ts`     | **robots.txt 生成器** - 调用 `robots.config.ts` 的 `generateRobots()`。                                                              |
| `src/app/sitemap.ts`    | **sitemap.xml 生成器** - 调用 `sitemap.config.ts` 的 `generateSitemap()`。                                                           |

> ⚠️ 本项目为静态导出，**不要新增 `src/app/loading.tsx`**（原因见 §5.2 注）。

#### 4.1.2 页面结构模式

目前存在两种页面结构模式，都以「服务端组件管 SEO + 客户端区块管交互」为原则：

**模式 A（31 个页面）：page.tsx 内联 Header/Footer**

```tsx
// 典型页面结构 (以 /banana 为例，实际代码)
import type { Metadata } from 'next'
import { Header } from '@/components/layout/Header'
import { Footer } from '@/components/layout/Footer'
import BananaProductPage from '@/components/sections/ai/BananaProductPage'

export const metadata: Metadata = {
  /* 页面专属 SEO 元数据 */
}

export default function BananaPage() {
  return (
    <>
      <Header /> {/* 全局导航栏 */}
      <main>
        <BananaProductPage /> {/* 页面主体区块（客户端组件） */}
      </main>
      <Footer /> {/* 全局页脚 */}
    </>
  )
}
```

**模式 B（14 个页面）：layout.tsx 使用统一外壳 `SiteShell`**

```tsx
// src/app/gpu/layout.tsx 等 14 处
import { SiteShell } from '@/components/layout/SiteShell'
export const metadata: Metadata = {
  /* 该路由的 SEO 元数据（各页保留，不可丢） */
}
export default function Layout({ children }) {
  return <SiteShell>{children}</SiteShell> // = Header + main.flex-grow + Footer
}
```

**设计模式说明**

- **服务端组件（`page.tsx` / `layout.tsx`）**：导出 `metadata`、渲染页面骨架
- **客户端区块（`components/sections/**`）**：交互逻辑（useState / Framer Motion / DOM）集中在区块组件，首行 `'use client'`；当前 51 个组件文件中 36 个为客户端组件

**`'use client'` 典型场景**：`Header`/`MobileMenu`（菜单开关）、`FloatingToolbar`（滚动显隐/弹窗）、`ServiceTabs`/`BentoGrids`/`Solution`（悬停切换）、`VideoCarousel`（自动播放）、`Analytics`（注入统计脚本）。

> ⚠️ 因 `unoptimized: true`，**`next/image` 只是普通 `<img>`**，不做任何尺寸/格式优化——图片优化必须在构建前用 `scripts/` 的流水线脚本完成。

> ⚠️ **Next 16 静态导出的 RSC 预取路径错位（上游 bug：vercel/next.js#85374，16.x 至今未修）**：产物把负载写成
> `out/<route>/__next.<seg>/__PAGE__.txt`，客户端预取却请求 `<route>/__next.<seg>.__PAGE__.txt` → 404，预取失效。
> 导航本身不受影响（点击时会回退到 `<route>/index.txt`），控制台会有 404 噪音。`postbuild` 钩子会执行
> `scripts/fix-rsc-prefetch.js` 复制一份正确命名的负载；**上游修复后删掉该脚本与 `postbuild` 钩子即可**。

### 7.5 npm scripts 一览（与 package.json 一致）

| 命令                                         | 说明                                                              |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `npm run dev`                                | 启动开发服务器（localhost:3000）                                  |
| `npm run build`                              | 构建并静态导出到 `out/`（自动执行 `postbuild` 修复 RSC 预取路径） |
| `npm start`                                  | 启动生产服务器（静态导出下一般不用，直接部署 `out/`）             |
| `npm run lint`                               | ESLint 检查（flat config，error 即失败；warn 只提示）             |
| `npm run typecheck`                          | `tsc --noEmit`                                                    |
| `npm run format`                             | Prettier 格式化 `src/**/*.{ts,tsx,css}`                           |
| `npm run images:optimize`                    | 图片批量转 WebP（流水线第一步）                                   |
| `npm run validate-seo` / `npm run seo:check` | 校验 `out/` 的 robots.txt / sitemap.xml                           |
| `prepare`                                    | `husky`（安装依赖时自动执行）                                     |

> ⚠️ **`npm run dev` 与 `npm run build` 现在可以同时跑**（Next 16 起 dev 产物写入 `.next/dev`，不再与 build 共用目录；
> 2026-09-22 升级后实测通过）。但**同一项目同时跑两个 `next dev` 实例会互相冲突**，并会让并行执行的 build 报
> `Cannot find module for page: /xxx`（2026-09-22 实测：两个 dev 实例 + build 时复现）。遇到该报错先检查是否有多个 dev 在跑；
> 仍可用 `rm -rf .next` 兜底重建。
> 纯静态导出项目每次硬刷新都要等 hydration 后才可交互，验证"首屏闪现/加载态"类问题时应重点看 `out/` 产物而非 dev。

## 8. 设计规范与约定

### 8.1 代码规范

完整、可执行的规范以 **`开发文档/代码规范与优化方案.md`** 为准（含 ESLint 规则、目录判定规则、Props 设计规范等）。此处仅列速查：

- **命名约定**:
  - 组件文件 `PascalCase.tsx`；Hook `useXxx.ts`；配置/工具/数据文件 `kebab-case.ts`
  - 组件导出：当前为混用状态（`sections/*` 多为 `default`，`layout/Header|Footer|Faqs` 为 named + default 双导出）——**新增组件统一 default export**（`app/**/page.tsx` 除外，固定 default）
  - 接口定义：优先就近定义；跨模块复用的放 `src/types/`
- **注释规范**: 公共接口用 JSDoc；内部细节用 `//` 且解释「为什么」；禁止复述型注释
- **文件组织**: 服务器组件放 `page.tsx`/`layout.tsx`；交互下沉到 `components/sections/**` 的客户端区块（现为 36/51 个组件带 `'use client'`）

### 8.2 UI 设计规范

设计规范与业务约束的**单一事实源是 `src/styles/tailwind.css` 的 Design Token**（旧 `.trae/rules/*.md` 为本地 AI 工具配置，未纳入版本控制，不可作为依据）。

**核心要点**:

| 要素         | 规范（以 tailwind.css 实值为准）                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| 设计风格     | 现代工业科技风 (Linear-style) + 便当盒布局 (Bento Grids)                                                                           |
| 默认模式     | **白天模式 (Light Mode)**                                                                                                          |
| 主色         | **`brand-500 = #3860f4`**（基于参考设计；`indigo-*`/`primary-*` 是它的迁移期别名，新代码用 `brand-*`）                             |
| 中性色       | `neutral-50 #f6f8fd` → `neutral-900 #1d273f`（标题 `neutral-800 #1d273f`、正文 `neutral-500 #50627f`、边框 `neutral-200 #dde3f2`） |
| 圆角         | `rounded-md` / `rounded-lg` / `rounded-xl`（token `--radius-sm…4xl`）                                                              |
| 字体         | 系统字体栈（`--font-sans` / `--font-display`），**零字体请求，禁止引入自定义字体**                                                 |
| 布局最大宽度 | 1800px（`Container`）                                                                                                              |
| 动画         | `framer-motion`（交互/切换）+ `tailwind.css` 内置 `animate-slide-up/fade-in/scan/float`                                            |
| 卡片 hover   | 细边框 → 边框变色 + 微阴影（优先复用 `.card-interactive`）                                                                         |

### 8.3 Git 提交规范

- 提交信息用**中文描述性语句**，多个改动点用「；」分隔（与仓库现有历史一致，如 `优化Advantage组件样式…；新增launch.json…`）
- 提交前由 husky + lint-staged 对暂存文件执行 `eslint --fix` + `prettier --write`（钩子已入库，本地 `npm install` 后即生效）
- 不提交构建产物（`.next/`、`out/`）与本地 AI 工具目录（见 `.gitignore`）
